# OpsPilot 5 分钟演示脚本

> 已生成无旁白自动演示：[OpsPilot-演示视频.mp4](OpsPilot-演示视频.mp4)（1 分 43 秒，1920×1080，已烧录中文字幕：章节标题 + 关键指标，无需配音）。本脚本为 5 分钟现场讲解版，口播内容与视频字幕一致，也可直接作为字幕文案维护。

> 目标：在 5 分钟内完整展示「故障注入 → 告警 → Agent 排查 → 人工审批 → 评测」闭环。
> 录制工具：OBS 或 Windows 自带录屏（Win + G）。建议 1920×1080，浏览器缩放 100%。

## 一、演示前准备（提前 3 分钟）

1. 启动：MySQL、`ollama.exe serve`、demo 服务（8081）、平台（8090）、前端（5173）。
2. 打开 4 个浏览器标签：
   - `http://localhost:5173/` 总览
   - `http://localhost:5173/faults` 演练台
   - `http://localhost:5173/incidents` 告警
   - `http://localhost:5173/eval` 评测中心
3. **预注入故障**（保证录制时告警已生成）：在演练台对「慢 SQL」设置强度 8、时长 300s，点击「注入故障」。
4. 等待约 40-60 秒，确认「告警」页出现 OPEN 事故，且总览页 P95 / DB RT 已抬升。
5. 确认 Ollama 已加载模型：`ollama list` 能看到 `qwen2.5:3b`；避免录制时首次加载卡顿，可先手动跑一次 Agent 预热。
6. 关闭无关窗口、通知与个人信息；数据库里保留最近一次 FULL_AGENT 评测（#18）用于展示。

## 二、时间线（总 5:00）

### 0:00 - 0:25 开场 + 总览

**画面**：总览页。

**口播**：
「这是 OpsPilot，一个面向 Spring Boot 服务的 AI 故障排查 Agent。左边是实时指标，右边是告警和 Agent 运行记录。现在我人为注入了一个慢 SQL 故障，可以看到 P95 延迟和 DB 响应时间已经明显抬升，系统自动生成了告警。」

**动作**：鼠标依次指 P95、DB RT、告警列表，不点击。

### 0:25 - 0:50 故障演练台

**画面**：切到 `/faults`。

**口播**：
「故障来自这个演练台。四类故障：慢 SQL、缓存击穿、线程池打满、下游超时，都可以调强度和时长。慢 SQL 会把列表查询退化成无索引全表扫描，所以 DB RT 和 P95 会同时升高。」

**动作**：指当前「演练中」的标签和实时指标卡，不重复注入。

### 0:50 - 1:10 告警详情

**画面**：切到 `/incidents`，点开最新事故。

**口播**：
「平台每 5 秒采集一次指标，按阈值评估后合并成事故。这条事故就是刚才的慢 SQL 触发的。」

**动作**：展示事故标题、严重级别、关联指标，停留在详情页。

### 1:10 - 3:20 Agent 排查（核心）

**画面**：切到 `/agent`，在「选择关联告警」中选中刚才的事故，补充输入「订单列表接口响应变慢，请排查根因并给出处置建议」，点击「开始排查」。

**口播**（执行过程中）：
「Agent 用的是自研 ReAct 循环，最多 6 步。每一步模型只能输出一个 JSON：要么调工具，要么给最终报告。它现在先查指标，再搜日志，接着看拓扑，然后直接给出处置建议——每一步查什么由模型决定，不是固定流水线。每次工具调用都会生成一条证据编号 E-xxxx，报告只能引用真实存在的证据。」

**动作**：等时间线逐步出现 `query_metrics`、`search_logs`、`get_service_topology`、`propose_remediation`、`REPORT`。不要催，让观众看到步骤流式出现。

**报告出现后口播**：
「报告里有根因、置信度、证据编号、影响面、处置建议和预防措施。根因是慢 SQL，引用了刚才指标和日志产生的证据。处置动作是 PENDING_APPROVAL，Agent 自己不会执行。」

**动作**：指根因卡片、证据编号、处置动作标签。可点开一条证据展示原始数据。

### 3:20 - 4:00 人工审批

**画面**：回到 `/incidents`，打开同一事故，滚动到「待审批处置」。

**口播**：
「危险动作必须人工审批。这里点批准并执行，平台才会调用 Demo 服务的处置接口，并把审批人、时间、参数、结果写进审计日志。」

**动作**：点「批准并执行」→ 确认弹窗 → 展示动作状态变为已执行/成功。回到总览，指出 P95 / DB RT 开始回落（若恢复需要时间，说明「处置已生效，指标会在下一个采集窗口回落」）。

### 4:00 - 4:40 评测中心

**画面**：切到 `/eval`。

**口播**：
「最后是评测。20 条场景，覆盖四类故障的不同强度和形态，对比三个基线：规则、只用 RAG、全工具 Agent。全工具 Top-1 是 19/20，95%；Top-3 是 20/20；平均 5.7 步、7.6 秒；证据准确率和报告完整率 100%；未授权写 0 次。只做 RAG 的基线 Top-1 只有 45%，说明检索到文档不等于能定位根因。」

**动作**：指汇总卡片和基线对比图，滚动逐场景表展示命中/未命中；必要时点「导出评测报告 JSON」。

### 4:40 - 5:00 收尾

**口播**：
「整个项目从采集、告警、工具链、ReAct Runtime、证据链、审批审计到评测都是我一个人实现的。当前定位是可演示、可评测、可回放的工程样板；上生产还需要接 Prometheus、ELK、K8s 和企业审批流，这些在 README 的已知限制里写清楚了。谢谢。」

## 四、常见问题与兜底

| 情况 | 处理 |
|---|---|
| 告警还没生成 | 提前注入并多等 30s；演示时直接讲「告警已生成」 |
| Ollama 未就绪 | 不要现场拉模型；提前预热，失败则展示历史运行 #118 的完整时间线并说明降级机制 |
| Agent 超时或降级 | 如实说明「小模型长对话偶发不稳定，Runtime 会重试并在连续失败后降级规则引擎」，再打开历史成功运行对比 |
| 审批后指标未立即回落 | 说明采集窗口为 5s，切到总览等待一个窗口再指指标 |
| 评测全量跑太久 | 演示只展示历史结果；如要现场跑，只勾选 3 条抽样场景 |
