# 告警治理与值班规范

## 告警分级
P1（全站不可用/资损）：电话+短信，5 分钟响应，30 分钟定位。P2（核心指标越线：p95>800ms、errorRate>5%、线程池>80%）：IM 强提醒，15 分钟响应。P3（趋势劣化）：邮件/工单，工作时间内处理。

## 告警质量治理
每周review告警：处理率低于 50% 的规则必须整改——要么调阈值，要么删。杜绝狼来了：同一规则一周触发 >10 次且无需动作，说明阈值太松；漏报一次 P1，说明覆盖不够。同服务同特征 10 分钟内的重复告警必须合并为一个 incident，避免轰炸。

## 值班处理流程
1. 认领告警，先看 get_incident_context 拿到告警+指标摘要+故障状态。
2. 按「指标 → 日志 → 变更 → Runbook」的固定顺序收集证据，不要跳步猜根因。
3. 处置动作必须走审批（WRITE 以上），Agent 建议仅供参考，人工确认后执行。
4. 恢复后写 incident 复盘：时间线、根因、处置、预防，更新对应 Runbook。

## 疲劳对抗
夜间告警设置升级链：值班人 5 分钟未响应自动升级给二线。长期「不用处理」的告警集中降级为周报指标，不进实时通道。

## 衡量指标
MTTA（平均响应）<5 分钟；MTTR（平均恢复）<30 分钟；告警处理率 >90%；误报率 <10%。OpsPilot 评测中心用 20 场景回归验证告警规则与 Agent 根因推断的准确率。
